## Подсказки на возможные вопросы

**«Почему `flask_jwt_extended`, а не `pyjwt`?»** — Потому что задание это явно требует («Для генерации токенов используется flask_jwt_extended»). По сути это обёртка над PyJWT с Flask-интеграцией (готовый `JWTManager`, конфиг через `app.config`).

**«Что такое CTE в SQL-запросе лидерборда?»** — Common Table Expression (с англ. *общее табличное выражение*), синтаксис `WITH name AS (...)`. По смыслу — временное имя для подзапроса, чтобы потом обращаться к нему как к таблице. Я использовал два CTE: `participations` (разворачиваю каждую игру в две строки — одну для X-игрока, одну для O) и `stats` (агрегирую по `user_id`).

**«Почему `GREATEST(losses + draws, 1)`?»** — Защита от деления на ноль. Если у игрока 5 побед и ни одного поражения, делитель будет 0 → ошибка БД или `infinity`. `GREATEST` берёт максимум из двух значений, поэтому делитель не упадёт ниже 1.

**«Где UUID попадает в токен?»** — В `JwtProvider.generate_access_token`: параметр `identity=str(user.id)`. В JWT это поле `sub` (от англ. *subject*) — стандартное поле в JWT (RFC 7519) для идентификатора владельца токена.

**«Что хранится в `g.current_user_id`?»** — `flask.g` (от англ. *globals*, глобальные переменные) — это контейнер для данных, живущих один HTTP-запрос. Кладу туда UUID после успешной валидации — это и есть аналог `SecurityContextHolder.setAuthentication` из Spring (упоминается в задании как «метод sign у расширения jwt для Request»).
